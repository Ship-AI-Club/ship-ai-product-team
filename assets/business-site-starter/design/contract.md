# Design contract

The Product Designer replaces this whole file before Frontend builds anything. A real (non-demo) build fails while this placeholder remains. Keep the finished contract to one page and send it directly to Frontend with its links or files.

## Direction
Privately compare 2-3 strong directions that fit this business. Record which were compared, the one selected and the rationale. If the owner explicitly chose a direction, write "Owner-chosen direction" and preserve it. Do not ask the owner to settle routine layout decisions.

## References
2-4 reference images saved in this project (for example `design/references/hero.png`) or accessible Cloud artifact links. Use your own renders. Never copy another company's artwork, identity or copy.

## Copy
Exact hero copy (eyebrow, headline, supporting line, primary CTA label) and exact first proof section copy. Use only approved facts from the brief.

## Type
Font families, weights and sizes for display, heading, body and small text on desktop and phone. Name the licence or source of each font.

## Tokens
Color tokens with hex values and their roles. Spacing and radius rules.

## Composition
The desktop (1440px) hero and first proof section: grid, scale, image placement, hierarchy and what fits in the first screen.

## Phone layout (390px)
The same two sections at 390px: order, sizes, line lengths and tap targets.

## Assets
Real or licensed imagery, illustration or product renders with their file paths and rights.

## Skill rules
3-5 lines. Each line names a skill, one rule from it and the concrete decision it caused, for example:
- skill-name: rule → decision
